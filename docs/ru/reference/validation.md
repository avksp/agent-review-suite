# Проверка ограниченного ввода

[English](../../reference/validation.md)

Используйте валидатор, чтобы сравнить документ ревью с доверенными
ожидаемыми привязками. Вызывающая сторона обязана (MUST) передать эти привязки
отдельным защищённым входом. CLI открывает только два указанных входа и
выдаёт результат в stdout или stderr. Параметр `-B` отключает запись
байткода Python.

```sh
python -B -m agent_review_suite validate --kind report --input report.json \
  --root /absolute/local/staging --expectations expected.json
```

Корень должен (MUST) быть абсолютным путём к локальному каталогу с физическими
компонентами. Пути к документу и привязкам указывают относительно корня.
Пустые компоненты, точки, две точки, обратная косая черта, двоеточие и NUL
отклоняются. Параметр `--input -` читает из stdin канал или обычный файл,
которым владеет вызывающая сторона. Ожидаемые привязки по-прежнему читаются
из контролируемого корня. Если оба входа получены из файлов, у них должны (MUST)
быть разные файловые идентификаторы. Помощник с закреплённым корнем отклоняет
повторный идентификатор файла. ARS не открывает пути из документа ревью.

Вызывающая сторона обязана (MUST) контролировать локальный каталог подготовки и
пресекать недоверенные изменения каталогов, точек монтирования и устройств.
Используйте локальную файловую систему. Если нужна жёсткая граница времени
при зависшей операции ОС, вызывающая сторона обязана (MUST) установить внешний
таймаут процесса. ARS проверяет единый монотонный дедлайн в две секунды для
обоих входов, включая ожидание конца канала. Вызывающая сторона обязана (MUST)
предоставить валидатору исключительный доступ к дескриптору канала на время
чтения. ARS восстанавливает режим блокировки канала при успехе и отказе.

Файловый ввод и stdin требуют поддерживаемых примитивов macOS или Linux.
Валидатор отклоняет символические и жёсткие ссылки, устройства, именованные
каналы, указанные путём, и наблюдаемые изменения идентичности файлов.
В Windows CLI отклоняет файловый ввод и stdin. Вызов из Windows может
передать байты в переносимый [API контрактов](request-report.md).

| Код | Значение |
| --- | --- |
| 0 | Оба документа корректны, ожидаемые привязки совпадают |
| 2 | Вход или аргумент некорректен, отклонён, слишком велик, вышел за дедлайн или не поддерживается |
| 3 | Оба документа корректны, но одна или несколько ожидаемых привязок расходятся |

Например, корректный отчёт с чужим идентификатором покрытия вернёт 3.
Если в нём также есть повторная строка покрытия, он вернёт 2. Состояние
выполнения ревью вызывающая сторона читает отдельно от результата проверки.
