# Подготовка поставки

[English](../../guides/releasing.md)

1. Соберите wheel, архив исходников (sdist) и ZIP плагина из одного дерева.
   Запишите коммит Git и ID дерева. Сохраните хеши архивов и списки файлов.
2. Проверьте публичные исходники и архивы на частные данные. Каждый архив
   обязан (MUST) содержать те же три схемы v1. Синтетические примеры могут
   входить только в sdist.
3. Установите wheel в чистое окружение. Запустите проверки установленных
   API и CLI. Сохраните локальные доказательства для независимого финального
   аудита и завершения.
4. Откройте PR в защищённую ветку. Проверьте, что дерево будущего merge
   совпадает с проверенным. Все 15 заданий CI должны (MUST) пройти на
   ревизии будущего merge. Повторите проверку при изменении базы или головы PR.

Например, вычислите SHA-256 схемы ожидаемых привязок в wheel, sdist и ZIP
плагина. Три хеша должны (MUST) совпасть.

## Подготовка PyPI

Проверьте метаданные wheel и sdist командой `python -m twine check --strict`.
Запишите имена и хеши обоих файлов. Набор для загрузки в PyPI содержит
только wheel и sdist. Храните ZIP плагина отдельно.

Для нового проекта владелец может настроить ожидающий Trusted Publisher с
точными именами репозитория GitHub, файла workflow и окружения. Ожидающая
настройка вступает в силу при первом использовании. Подтвердите контроль
над именем проекта перед публикацией.
[PyPI Trusted Publishing](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/)

Владелец выпуска обязан (MUST) разрешить публикацию до активации publisher
или загрузки. Проверьте workflow, точный набор файлов загрузки и их хеши. После
разрешённой публикации проверьте артефакты в GitHub и PyPI и чистую установку
из PyPI. Зафиксируйте результаты аудита после публикации.
