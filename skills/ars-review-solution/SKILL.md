# ars-review-solution

Read [the review boundary](references/boundary.md) before this role.

Review the proposed design, not implementation. Check requirement fit, actual integration boundaries, security, resources, feasibility and testability. Compare the current/no-change option and only meaningful alternatives. Explain the smallest sufficient choice and its unresolved evidence. Leave product scope decisions with the owner.

This is guidance-only bootstrap content; caller permissions and acceptance remain authoritative.

Use the ARS v1 validator when the caller supplies review bytes and separate
protected expectations. A matching format and binding leaves semantic review
and acceptance with the caller.
