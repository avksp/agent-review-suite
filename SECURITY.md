# Security policy

Report suspected vulnerabilities privately. Use **Report a vulnerability** in
the repository's Security tab if GitHub offers it. You can also contact the
repository owner through a private channel. Keep reports with sensitive details
out of public issues.

Include the ARS version or commit, platform, affected boundary, and observed
behavior. Use synthetic inputs. Remove credentials, personal session data, and
private evidence from attachments.

The [threat model](docs/architecture/threat-model.md) describes the trust
boundaries. Report failures in input limits, file intake, expectation matching,
or distribution checks.
